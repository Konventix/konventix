## Task 23: Partial cancellation with a per-unit refund (Registration, Commerce) — D-REG-15

**Investigation (2026-09-21):** the console refunds whole orders only; `RefundOrder` accepts a partial amount but `RecordRefund` then forces `OrderStatus::Refunded` and refuses a second refund, `IssueCreditNote` copies the invoice's net and tax and overrides only gross (#7 — the rendered VAT rate is then false), and a partial refund triggers nothing in Registration. Grants are multiplied once in `ConfirmRegistration`, so Admission and Resources know no quantity; a negative `RegistrationAmended` would break their idempotency and the cancellation arithmetic. **Decisions:** operator-only, from a Registration-owned console action (ADR-0004 forbids Commerce calling a Registration Action); Registration first, Commerce reacts to a new event; Admission refuses when fewer than N admissions are free (unassigned, unclaimed, unseated, never checked in); the per-unit credit note is exactly computable from one order line at one rate, so #7's general allocation stays open; the waitlist stays one unit; `registration.desk` does not get the new capability; buyer self-service is a later item.

## Task 25: Sessions list on redis through a per-user session index (Identity) — D-IDP-17

**Investigation (2026-09-21):** Laravel 13 has no `RedisSessionHandler`; `SessionManager::createRedisDriver()` builds a `CacheBasedSessionHandler` over the redis cache store. `SecurityController` hard-codes availability to the database driver; `ActiveSessionsQuery`/`SessionController` read and delete `sessions` rows directly. The handler is the only hook that sees every moment (activity on every `write()`, id rotation at login, every login path, logout — where Fortify empties the guard before `invalidate()`, so `destroy()` must learn the owner from the stored meta hash). Under Octane the handler is a worker-lifetime singleton that gets no new container, so request, user and IP are resolved per call, never captured. `Session::extend('redis', …)` outranks the stock creator and keeps encryption and JSON serialization, so no env or chart value changes.

- [x] Investigation report and task text.
- [x] `Sessions\IndexedRedisSessionHandler extends CacheBasedSessionHandler`: `write()` → `parent::write()`, then only for a signed-in user HSET `sessions:meta:<id>` `{ip_address, user_agent (truncated as `DatabaseSessionHandler` does), user_id, last_activity}`, SADD `sessions:user:<ulid>`, EXPIRE both with `session.lifetime * 60`; `destroy()` reads the meta hash first, SREMs, DELs, then `parent::destroy()`. Request/user/IP via `request()`/`auth()` per call; nothing in the constructor.
- [x] Registered in `IdentityServiceProvider::registerBindings()` as `Session::extend('redis', …)`, repeating `createRedisDriver()`'s store wiring (`session.store`, `session.connection`, `session.prefix`) with a docblock naming that source and the Octane no-op listeners.
- [x] `Sessions\SessionRepository` (`available()`, `activeFor(User)`, `revoke(User, $id)`, `revokeOthers(User, $exceptId)`) with `DatabaseSessionRepository` (wrapping `ActiveSessionsQuery` and the two deletes), `RedisSessionIndexRepository`, and a null implementation for array/file/cookie; bound with `bind()` on `config('session.driver')`; the redis `available()` asserts `session()->getHandler() instanceof IndexedRedisSessionHandler`.
- [x] `SessionSummary` value object; `SessionData::fromSummary()` replaces `fromModel()`; `SecurityController` and `SessionController` depend on the repository only; `sessionsAvailable` = `$this->sessions->available()`; `SessionList.vue` unchanged.
- [x] Expiry: meta TTL re-set on every write; `activeFor()` prunes ids whose hash is gone and filters `last_activity >= now - lifetime`; the user set's TTL refreshed on write. No gc, no job.
- [x] Index operations behind a `SessionIndex` interface (redis and cache-backed implementations) so the repository contract test runs on the array store; one real-redis integration test for the handler end-to-end that skips when redis is unreachable, uses a test-only key prefix and deletes only the exact keys it created (`RedisWaitingRoomStoreTest`, `MetricsRedisStorageTest` traps); one Octane-staleness test (two simulated requests through one handler instance record their own IP and user).
